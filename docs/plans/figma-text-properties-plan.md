# Figma text properties: consumer text editable from the right panel

Package: `.claude/skills/ds-code-to-figma`

Status: Decisions agreed (grilling session 10.11.2026). Skill steps implemented 10.11.2026. Verify run: `ds-button` (blocked on `/update-screenshots`) and `ds-input` (pass) done 11.11.2026, both on Figma branch `TMW8IfOY7LbN3IXvu3cI15`; findings folded into the skill (see each `*.figma-validation.md`). The Figma branch was merged into main 11.11.2026.

## Goal

Every text a consumer writes in code is a Figma `TEXT` component property, bound to its text node.
A designer edits a button's label, an input's label / value / placeholder / description from the
right panel, without double-clicking into the component. Applies to every component the skill
builds.

Replaces today's `instance-text-override` mapping (`PHASE-2-PROPOSE.md` step 1 table, "Free-text
prop" row): text was only editable by clicking into the layer.

## Decisions

| #   | Decision |
| --- | --- |
| 1   | **Scope = consumer-authored text:** (a) string props rendered as text (`label`, `description`, `placeholder`, `value`, `invalidText`), (b) text-only slots (`ds-button`'s default slot = its label). Text the component generates itself (pagination page numbers, counter digits, weekday names) stays plain text, no property. |
| 2   | **Binding:** `set.addComponentProperty('<name>', 'TEXT', <default>)` on the component set; `textNode.componentPropertyReferences = { characters: <key> }` on the matching node in **every** variant. Mapping-file value `figmaPropertyType: text` replaces `instance-text-override` everywhere. |
| 3   | **Naming:** per `PHASE-2-PROPOSE.md` → "Naming" — the code prop, lowercase with spaces (`invalidText` → `invalid text`). A text-only slot is named after its `@part` (button default slot → `label`). |
| 4   | **Default text:** always the property name in sentence case (`Label`, `Placeholder`, `Value`, `Description`, `Invalid text`). No Storybook lookup, no question. Drops the "ask if code default is `''`" rule. |
| 5   | **Render-guarded text** (`hasValue(x) && <span>`): the existing `show <name>` boolean stays, alongside the `TEXT` property. |
| 6   | **One node, two props, different tokens** (`ds-input`'s `input` part shows `value`, else `placeholder` with the placeholder color): two text nodes, each with its own `TEXT` property and its own color token, plus a **`filled` variant property** (`false` default — code default `value = null`). `filled=false` variants show only the placeholder node, `filled=true` only the value node (static `visible`, no boolean). Counts toward the 500-variant check (Input: 60 → 120). |
| 7   | **One node, two props, an existing variant decides** (`description` part shows `invalidText` when invalid): two nodes, `description` and `invalid text`, each with its own `TEXT` property. Visibility wired per variant by the existing axis (`color=invalid` → `invalid text` node, others → `description` node). The `show description` boolean binds to whichever node is active in that variant; the other is statically hidden. No new axis. |
| 8   | **Nested non-slot DS instance with `TEXT` properties:** `isExposedInstance = true`, so its properties appear on the parent instance. Accepted risk: parent-driven child props (e.g. size) become editable too. Icon slots stay unexposed. Sub-components in a native `SLOT` carry their own `TEXT` properties (selected directly). |
| 9   | **Panel order:** create `TEXT` properties in render order (top → bottom in the component), so the panel reads like the component. |
| 10  | **Validation:** Phase 4 checks every `figmaPropertyType: text` prop exists as a `TEXT` property with the agreed name/default, and is bound (`componentPropertyReferences.characters`) on every variant where its node exists. |
| 11  | **No migration:** existing `*.figma.md` files (button, input, close, spinner, pagination, icon, logo) are regenerated by a later run, not patched (skill is in POC phase). No ADR — cheap to reverse. |

## Implementation steps

All edits in `.claude/skills/ds-code-to-figma/`. Never touch component source or Figma in this
plan.

### 1. Glossary — `CONVENTIONS.md`

- Add **text property**: "A Figma `TEXT` component property bound to a text node's `characters`;
  one per consumer-authored text (string prop or text-only slot)." Don't say: _instance text
  override, text override_.
- Add **consumer-authored text** (decision 1) — the scope term, with "generated text" as its
  counterpart.

### 2. Phase 1 — `PHASE-1-ANALYZE.md`

- Step 1 (props): for each string prop, record whether it renders as text and in which `@part`.
- Step 2 (anatomy) or new sub-step: find text-only slots (default slot whose content is text,
  e.g. button label) and record them as text props with the `@part` name.
- Flag shared-node cases: one part rendering two props (decisions 6, 7) — record which prop wins
  under which condition and whether the token differs.
- Record generated text explicitly as "generated — no property" so the omission is visible.

### 3. Phase 2 — `PHASE-2-PROPOSE.md`

- Mapping table: replace the "Free-text prop" row with **Text property** (decisions 2–4).
- Update the "Free-text prop guarded in `render()`" row: `TEXT` property + `show <name>` boolean.
- Add row **One node, two props, different token** → two nodes + `filled` variant (decision 6),
  counted in step 3.
- Add row **One node, two props, existing variant decides** → two nodes, per-variant visibility
  (decision 7).
- Add row **Nested non-slot DS instance with text properties** → exposed instance (decision 8).
- Naming: add the slot-text rule (decision 3) and the sentence-case default (decision 4).
- Step 5 sign-off: the proposal lists every text property (name, node, default) and every
  generated text left without one.

### 4. Phase 3 — `PHASE-3-BUILD.md`

- Step 3 (default variant): build each text node with its default characters and tokens first.
- After `combineAsVariants()`: add the `TEXT` properties on the set in render order, then set
  `componentPropertyReferences = { characters: key }` on every variant's node. Note the mechanics
  in `conventions/build-mechanics.md`:
  - The property key comes back suffixed (`label#123:4`) — store it, use it for references and
    `setProperties`.
  - Load the node's fonts before binding; binding writes `characters`, which resets per-range
    styling — re-check that token bindings (`fontFamily`, `fontSize`, `fills`, `letterSpacing`)
    survive the binding; if not, bind the text property **before** the token bindings.
  - A node can carry both `characters` and `visible` references at once (`show <name>` + text).
- Decision 6: build both nodes in every variant; `filled` axis sets static `visible`.
- Decision 7: per-variant `visible` reference / static hide.
- Decision 8: `isExposedInstance = true` on nested non-slot instances with `TEXT` properties.
- Slot default fills (`conventions/families.md` §4, e.g. 3 × `Tab` with labels): set labels via
  `instance.setProperties({ [key]: 'Tab 1' })`, not by editing `characters`.
- First-variant checkpoint: state which text properties exist, so the user can try them in Figma.

### 5. Phase 4 — `PHASE-4-VALIDATE.md`

- Step 3: add the text-property check (decision 10) — name, type `TEXT`, default, bound on every
  variant; no consumer-authored text node left unbound; no generated text bound.
- Step 4: exposed nested instances match decision 8.

### 6. Phases 6–8 — check only

- Phase 6 (Copy me): "override nothing" still holds — instances show the sentence-case defaults.
- Phase 7/8: text nodes keep their layer names, so anatomy markers and `Text (<part>)` rows still
  resolve. With two nodes per part (decisions 6, 7), measure/annotate the visible one in the
  default variant.

### 7. Schema and topic files

- `examples/mapping-file-format.md`: `figmaPropertyType: text`, plus fields `node:` (layer name),
  `default:` (sentence case), and for shared nodes `shownWhen:` (e.g. `filled=true`,
  `color=invalid`).
- `conventions/content-selection-and-mitigations.md` → "Prop-to-variant mapping": mention text
  properties in the pointer list.
- `conventions/families.md` §4: slot placeholder text set via text properties.
- `DECISIONS.md` Phase 2: remove the "code default `''`" ask; ambiguous text source (can't tell if
  text is consumer-authored or generated) → hard stop under "Ambiguous prop-to-variant mapping".

### 8. Verify on a real run

- Re-run the skill for `ds-button` (decisions 1b, 5, 3) and `ds-input` (decisions 6, 7) on
  a throwaway branch of the Figma file; confirm in Figma that every text is editable from the
  panel, the `filled` and `color=invalid` swaps show the right node, and Phase 4 passes.
- Feed any Plugin API surprise back into `conventions/build-mechanics.md`.

## Open questions

- None blocking. Decision 8's accepted risk (parent-driven child props editable) can be revisited
  if consumers break instances in practice.
